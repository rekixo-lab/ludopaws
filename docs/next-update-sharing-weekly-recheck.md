# Sharing, room links and weekly challenges — source recheck

Branch: `codex/next-update-comeback-bonus`. For the next update only. No tests, build, app execution, CI, deployment, merge, Play listing changes or Play release were run. Source review is not device/runtime validation.

## Included

- Explicit SHARE action after finished Online, Friends, Team Up, Pass & Play, Robot and local Quick Match results. A 1080px PNG uses the installed animal avatar renderer, game branding and actual win/rematch/celebration copy. No automatic sharing or reward for sharing. No player names, IDs, room tokens, wallet, screenshots of other UI or third-party contacts. Finished-room codes are deliberately not attached to result cards.
- Native Android chooser with a temporary read-only content URI; FileProvider exposes only `cache/share_cards/`, not all cache/files. Card drawing/compression runs on a single background worker, duplicate taps are blocked and background/destroyed hosts do not open a chooser. Old attachments expire from cache on a later share after seven days. A chooser opening is counted locally; it is not reported as a completed share or install.
- Friends waiting-room shares now use HTTPS `/play/friends/ROOM` links. A host can include their own public Friend ID; player/session tokens never leave the app. The dedicated exported activity validates scheme, host, port, room/mode and optional Friend ID, and preserves privacy/online safety gates. It never launches Home's abandoned-match cleanup, silently abandons an existing room, or auto-joins.
- An existing recipient invitation for that exact room gets a direct JOIN FRIEND'S ROOM action, using the unchanged accepted-invite token and server validation. A new friend can request the host from the link; the host must still accept friendship and send the room invite. Links do **not** bypass friendship, blocks, invitation expiry or room capacity. Public Online has automatic matchmaking and no manual Join UI, so no nonfunctional Online room link was added. Team Up remains matchmaking-only.
- Browser fallback with open-app and Google Play buttons, visible room code, and explicit instructions to reopen the same invitation after install/update. No deferred-install SDK or automatic install attribution is added. A matching Worker deployment and existing Play signing certificate association are required for HTTPS link/browser support at release time; neither was deployed here.
- Rewards hub shows a rotating weekly challenge: finish three games, finish on two UTC days, or use three different pals in completed games. Changes each Monday 00:00 UTC, displays the next change in local time. Wins optional; all game modes count. No pop-up or fee, currency, ad, leaderboard or paid advantage. The device/account-local Weekly Paws badge and badge count appear in Profile, and the challenge has its own optional share card. These are local display badges, not shop entitlements or cloud-restored rewards; reinstall/deletion can remove them.
- Completion writes are idempotent across repeated result updates and week boundaries; previous-week recovery is not credited to a later challenge. Offline pending results carry their completion timestamp and pinned owner. Online completion requires an authoritative finished result with winning paws home, rather than a loss/forfeit counter. Account deletion clears the new preference scope and late deleted-account recovery is ignored. Bounded match-ID history is local only; it is not an anti-cheat or server clock authority.
