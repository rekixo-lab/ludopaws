# Ludo Paws

**Publisher:** Rekixo  
**Android application ID:** com.rekixo.ludopaws  
**Game site:** https://ludopaws.rekixo.com  
**API:** https://api.ludopaws.rekixo.com

Ludo Paws is a native Kotlin Android Ludo game with an authoritative Cloudflare Worker and Durable Object backend.

## Architecture

- Android: native client, animations, Robot and Pass & Play.
- Server: authoritative match state, turn rules, online sessions, matchmaking, Friends, Team Up, Quick Chat, leaderboard and account/store APIs.
- Docs: implementation notes, platform setup and release checks.

The Worker and Durable Objects are authoritative for online seats, turns, dice outcomes, legal moves, captures, safe cells, extra turns, third-consecutive-six handling, winners and replay-safe mutation handling. Android consumes returned state; it does not choose online dice outcomes.

## Native dice

Online rolls are generated by the Ludo Paws server using the platform cryptographic random-number generator. Rejection sampling maps random 32-bit words uniformly to faces 1–6. Each receipt binds the result to match/event/player context and is persisted with match history in the same serialized room mutation.

Offline Robot and Pass & Play use Android SecureRandom and a local receipt. Local receipt checks can identify inconsistent stored data, but a locally controlled device is not an independent fairness authority. Server receipts document the outcome and event context; they are not third-party cryptographic certification. Do not market the game as independently audited or certified without external review.

## Online gameplay performance

The client uses a shared pooled OkHttp client for REST and the realtime WebSocket. A new dice roll uses one client request instead of separate commit and reveal calls. Native roll handling and authoritative state persistence happen within the match room. Rate limits remain enabled, and the existing Durable Object gate is retained as a fallback if an edge limiter is absent or unavailable.

These changes remove avoidable request overhead but do not guarantee a specific latency. Measure real-device latency, reconnect behavior and gameplay on realistic networks before release.

## Local verification

Server: run npm test from the server directory, then run the Wrangler deploy dry-run.

Android: run the app's Debug unit tests, Release lint and Debug APK assembly with Gradle.

GitHub Actions runs repository CI on the performance branch. A passing build is not a substitute for testing real multiplayer sessions on devices.

## Deployment safety

Production deployment is manual and restricted to main. The production workflow must not run from this working branch or publish to a live Worker by itself. Keep Cloudflare session-signing secrets and Google Play service-account credentials server-side; never include them in Android source or commit them to the repository.
